## Complete Planning Workflow

### Step 1: Project Initialization
```
I want to start a new project. Here are my initial requirements:

[YOUR_REQUIREMENTS]

Please use the gap analysis template to help me clarify all the technical details needed for a successful implementation.
```

### Step 2: Architecture Planning
```
Based on our clarified requirements, please create a detailed system architecture plan using the architecture planning template.
```

### Step 3: Implementation Phases
```
Now that we have the architecture, please break this down into detailed implementation phases using the implementation phases template.
```

### Step 4: Phase-by-Phase Implementation
```
Let's implement Phase 1. Please provide:
- Specific implementation steps
- Code examples and patterns
- Testing approach
- Success criteria
```

### Step 5: Verification and Review
```
Please review the implemented code using the code review template to identify any issues that need to be addressed.
```

## Best Practices

### 1. Always Start with Gap Analysis
- Don't jump into implementation
- Ask clarifying questions first
- Ensure complete requirements

### 2. Use Structured Responses
- Follow the template formats
- Provide clear next steps
- Document decisions and reasoning

### 3. Iterate and Refine
- Review plans before implementation
- Adjust based on new information
- Continuously verify against requirements

### 4. Maintain Context
- Reference previous decisions
- Keep track of changes
- Document trade-offs and alternatives

### 5. Test and Verify
- Review code at each phase
- Verify against original requirements
- Identify and fix issues early

## Troubleshooting

### Common Issues
- **Vague Requirements**: Use gap analysis prompts to clarify
- **Missing Dependencies**: Use architecture planning to identify
- **Implementation Gaps**: Use verification prompts to catch
- **Performance Issues**: Use performance planning to address
- **Security Concerns**: Use security planning to mitigate

### Getting Better Results
- Be specific in your requirements
- Ask follow-up questions
- Provide context and constraints
- Review and iterate on plans
- Use verification at each step
